# 模型候选与默认选择 · 2026-10-23

目标：用户进来优先使用近期可用模型，免费额度耗尽后不再反复选择失败项。该功能不查询或推算云端免费余额，不增加探测推理，不自动切换模型重试或关闭思考。

## 实现与边界

- 真实运行的成功与安全错误分类写入 Web 数据库，按服务端点、账户指纹与 live/mock 分隔；原始密钥和错误正文不写入可用性表。
- 明确免费额度耗尽、模型不存在/不可用才作模型级隐藏；普通 400/404/422 为配置级拒绝，429 普通限流不视为永久耗尽。
- 默认推荐要求 24 小时内相同配置成功；不覆盖未失败的手动选择，不改变活动运行或启用已暂停调用。
- 恢复按钮只清除本地阻止，重新标为未验证，不发请求。模型列表能列出某 ID，不代表推理可用或免费余额充足。
- 新建独立任务继承主对话的模型/推理偏好，但不继承调用暂停开关；后台派发保留现有完整配置继承策略。
- 界面沿用白色、冷灰和原有控件，只增加候选状态及折叠的不可用项，不增加装饰卡片。

用户确认并已实际使用 `qwen3.5-flash`；现有成功运行的请求及返回模型 ID 一致。重启后仅将这条用户确认的成功记录登记到当前服务/账户的可用性状态，先核对保存配置与当前配置一致，使用原运行时间；不批量导入无账户指纹的旧历史。本轮未再发推理验证，也未改写 `.env` 或推测其他模型的免费余额。旧 deepseek HTTP 400 缺少原始服务错误码，不能断言是免费额度耗尽。

阿里错误语义参照 [免费额度说明](https://help.aliyun.com/en/model-studio/new-free-quota) 和 [错误码](https://help.aliyun.com/en/model-studio/error-code)：免费额度停止与普通 TPS/TPM 限流必须区分。兼容网关若丢失详细错误码，只能保留未知或配置拒绝状态。
