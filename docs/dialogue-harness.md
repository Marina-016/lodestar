# 简单的对话 Harness

2026-10-09：普通对话由模型决策，回答直接使用模型生成的 Markdown。

```text
用户消息 + 历史 + 记忆 + 当前时间
                 ↓
             模型决定下一步 ←── 工具结果
                 ↓                  ↑
        搜索 / 发现 / 阅读 / 项目检索
                 ↓
     模型基于完整摘要或正文自然回答
                 ↓
       保存会话，独立更新方法接触记录
```

没有自然语言关键词分流；不强制回答分成事实、背景、推测、缺口等类型。
没有普通回答的逐字引文门禁、格式修复轮次或替换中文介绍的固定链接渲染。
用户提问决定解释深度与格式，模型自主消歧、选择查询、比较论文和给建议。

arXiv 与 HF 返回完整 abstract；snippet 保留给旧检索消费者。
完整摘要可直接支持导读，无需为了讲摘要再读取同一篇论文。
模型说明摘要级解读与正文分析的区别，来源链接由模型自然放置，不每篇重复警告。
网页搜索 snippet 仍明确标为 search_snippet，不能称为完整摘要或正文。

宿主保留工具参数解析、只读权限、会话/项目隔离、预算、重复调用检测、
外发授权，以及独立的学习记忆来源校验。检索客户端负责共享限流/冷却/缓存，
详见 [论文检索可靠性](retrieval-reliability.md)。

显式 research / plan / feedback 接口继续存在；结构化方案和实验有各自的契约，
普通聊天不套用这些契约。讲解的 contract_valid 仅表示返回了非空文本，
validation_scope 明确不代表事实准确性、实验收益或用户掌握已通过验证。

记忆更新独立于回答展示，继续校验具体方法是否同时出现在已读来源与已送达回答。
仅浏览摘要列表不会自动提升掌握；概念定义不应作为个人学习事实，用户自评不等于掌握。
普通回答不再通过宿主逐句事实筛查，错误归因/不受支持概括仍可能发生，需要真实质量评估。

## 验证重点

完整摘要末尾能进入模型、中文介绍和比较完整送达、Markdown/表格/代码不被重排、
没有隐藏 JSON 格式要求和修复重试；旧方案/实验契约、权限和方法接触校验继续回归。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -q
```

实际根因记录：用户“ai最近有什么论文吗”这轮，模型已生成四段中文摘要，
旧 source 渲染器忽略 text 并替换成标题链接；测试只检查链接，漏掉了中文介绍丢失。
本次删除整个普通回答分块渲染器，避免再添加更多特殊规则。
