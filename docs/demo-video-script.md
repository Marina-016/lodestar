# Lodestar v0 Demo 视频脚本

## 一句话主题

Lodestar 把一个模糊的学术问题，变成有证据、有记忆、可验证的下一步。

## 视频目标

这不是一个“AI 搜索框”演示，而是展示一条完整的研究闭环：

```text
提出问题 → Agent 选择研究路径 → 检索与综合证据 → 更新个人知识 → 生成可验证实验
```

它体现 AI 产品经理的四项能力：问题定义、Agent 工作流设计、知识状态设计，以及从洞察到验证的产品闭环。

## 第一版录制范围

- 时长：60–75 秒
- 画面：16:9，只录 Lodestar 内容区，不录浏览器标签栏和大面积空白
- 第一版：无字幕、无配音、无额外动效
- 录制时展示可观察的 Agent 工作过程，不展示模型内部隐藏推理

## 录制脚本

### 1. 从一个问题开始（0–6 秒）

画面停留在“研究对话”首页，在输入框输入：

> 帮我研究本周 Agent Memory 的学术热点：找出最值得关注的一条，解释它对 Lodestar 的启发，并给出一个可验证实验。

点击发送后停留片刻，让观众看到问题是从对话框进入研究流程的。

### 2. Agent 开始研究（6–16 秒）

保持在研究进度状态，展示：理解问题、选择研究路径、检索来源、记录研究步骤。

这里表达的是 Agent 的外显工作流，而不是模型的隐藏思维过程。

### 3. 生成研究结论（16–30 秒）

展示核心结论、Why it matters、与 Lodestar 的关联，然后向下滚动展示 Evidence Trail、论文来源和 PDF/预印本信息。

### 4. 把理解写入知识库（30–42 秒）

滚动到“把这次理解留在 Knowledge State”，点击“记住选中的结论”，等待“已更新知识”，再进入“知识库”页面，展示 Agent Memory 概念已经进入个人知识状态。

### 5. 从知识到实验（42–58 秒）

进入“实验项目”，找到“带反思的 Knowledge State 是否能减少重复检索？”，点击“生成骨架”，展示实验从 draft 变成 built，以及生成后的实验标题、假设和基础结构。

### 6. 结尾画面（58–75 秒）

停留在已生成的实验骨架页面，然后回到研究对话首页。最后让观众记住：

```text
热点发现 → 证据理解 → 认知更新 → 实验验证
```

## 后期旁白草稿

> 我不想只让 AI 告诉我一个答案，我希望它能帮我完成一次真正的研究。
>
> Lodestar 会先理解我的问题，再选择研究路径，检索相关论文和资料，并把结果和我正在做的项目联系起来。
>
> 它给我的不只是几篇链接，而是告诉我这个方向为什么重要，哪些是共识，哪些是真正的新变化。
>
> 当我确认这条结论值得长期保留时，它会进入我的知识状态。下一次研究时，Agent 不需要从零开始。
>
> 更重要的是，研究结果不会停留在笔记里。Lodestar 会把一个研究判断转成可以验证的实验。
>
> 这不是一个会聊天的搜索框，而是一位研究搭档：帮助我发现问题、理解证据、更新认知，并验证判断。
