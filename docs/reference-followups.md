# 选段追问、简短确认与重复回答（2026-11-11）

## 已观察到的问题

用户连续引用 `verifier` 询问中文和词义，选段已完整保存为 `> verifier`，但两条回答逐字相同，都是 723 字的旧论文背景。没有发现 HTML 空格实体导致引用丢失，也没有应用层答案缓存。原请求包含约 38173 字符、15069 prompt tokens。

同一点点模型 `dots3-note-prev`，保持关闭思考，用只读重放对比：无历史短请求能正确翻译；只带有界历史、或只带论文资料，也能回答词义；历史与资料同时作为原生多轮上下文带入时反复输出旧稿。仅增强提示、缩短历史、合并相邻 user 消息或删除记忆，均未解决该样本；不据此断言上游缓存或模型实现存在某个具体缺陷。

## 实现

- 当前选段与当前问题放在请求末尾紧邻位置；引用仍是待处理的数据，不能作为系统指令。
- 每轮新用户消息都把已保存历史作为明确标注的参考数据，不再放成原生 assistant 角色让模型继续模仿旧稿；不再只覆盖选段分支。本轮新生成的工具调用和结果仍使用原生块，工具标识和权限不变。“继续生成”按钮的原位追加流程保持独立。
- 有选段时，近期历史限 8000 字符，每条旧回答保留最多约 1200 字符，重复回答仅保留一个近期实例，用户的纠正和当前提问保留。无选段时沿用原有 24000 字符历史预算。
- 当前问题旁边附上最近一条已发送回答的末尾（最多 700 字符）作为交接点。它是待理解的历史数据，不是要求重播的正文；短确认有唯一待讲部分时应向前推进，无待讲内容时简短接住。不是按 ok 关键词映射固定回答，也不新增长期记忆。上下文退役后重新计算交接点，不残留已清除的内容。
- 选段追问默认只携带继承资料的标题、链接、日期和简短摘要等来源索引。保留 `previous_read_depth`，用 `body_context_omitted` 区分本轮是否有正文；需要具体原文依据时仍可调用读取工具，本轮新读片段会进入最终证据包。
- 上述只改变模型提示视图，不删除旧消息，不更改保存在数据库中的论文正文、来源追溯和阅读记录。
- 对“每次只讲一部分”的要求，明确一次推进一个小概念；问词义时先定义或翻译，不沿用上一轮的论文讲解计划。

## 验收

只读脚本：`python -m scripts.check_reference_followup --message <用户消息 ID>`；加 `--live` 才调用一次当前模型，不执行工具，不写入聊天，不自动重试，不保存原始提示。

正式结构对原来两条失败提问均返回“verifier 中文是验证器”，随后解释判定程序并给出小例子，没有复述旧论文背景；两次均未申请工具。历史字符约 4674/5106，总请求字符约 19497/19945，原轮次约 38173。实测不是对所有问题或所有上游负载的行为保证。

回归覆盖引用不进入 system、当前选段只出现一次、历史去重和用户纠正保留、预留回答阶段的引用保持、继承正文省略而本轮读取证据保留，以及对话、记忆隔离、论文指代和续写兼容性。

## 普通确认的补充验收

后续出现未引用的“ok”复读实验章节，上一条末尾实际已提出继续下一部分。这暴露了首次修复只覆盖选段请求的缺口，现统一初次模型请求与工具预算耗尽后的回答视图，并将最近交接点放到当前问题旁。

`python -m scripts.check_dialogue_progress --live` 只生成虚构课程对话，不读取数据库或用户记忆，固定使用现有点点接口。单一待讲部分、一个具体下一节附“还是想问别的”的礼貌出口、没有待讲内容，均能避免复读已完成部分。两个并列的明确选项时，当前模型仍可能选首项而非澄清，不能将普通 ok 视为严格的选项确认协议。

获准的一条真实“我懂了，你继续吧”重放已转向后续部分；最新真实 ok 的在线重放被自动审批拒绝，理由是私密上下文外发的范围和目的地未明确，未通过其他路径重试。该条只做本地只读组装验证，在线行为改用合成对话验收。测试不改写真实消息，不自动重试，不升级思考模式。
