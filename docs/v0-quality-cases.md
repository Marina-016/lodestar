# V0 质量验收卡

更新：2026-10-17。范围：本地单用户 Web 研究闭环。产品边界以 [当前 PRD](agent-prd.md) 为准；历史失败见 [10-14](v0-live-review-20261014.md) 与 [10-15](v0-live-review-20261015.md)。

本页是待执行的人工验收协议，不是已通过报告。模型负责理解语言与选择工具；验收卡不要求固定搜索顺序、最低阅读篇数、固定回答模板、关键词路由或额外反思 Agent。

## 执行准备与记录规则

1. 每组使用全新的隔离验收目录和数据库；第 1、3、4、5、7 组的连续消息保留在各自同一会话。禁止打开或修改真实用户库，不复制 .env、密钥、真实研究内容。
2. 记录 commit、运行模式、模型 ID、思考参数、工具预算、数据版本和开始时间。比较修改前后时固定这些条件；模型或思考变化作为另一项实验。
3. 分清三种证明范围：
   - 合成模型 + 固定工具结果：仅证明宿主功能与状态流转。
   - 真实模型 + 固定工具结果：可审阅该模型在受控证据上的语义，不能证明真实检索/阅读服务可用。
   - 真实模型 + 公开检索/阅读：同时审阅服务与回答；须保存实际来源快照，不能套用固定夹具的标准答案。
4. 真实模型运行前重新核实当前免费额度、模型服务可用性和资料授权，设置整轮物理请求上限；前台、子任务和学习提取共用上限。不得自动切付费模型、收费搜索或隐藏重试。历史免费额度不作为本次依据。
5. 冻结来源正文与元数据，记录快照路径/哈希、URL、版本、获取时间、片段位置和阅读范围。人工标注应先于被测回答；不得让同一个模型生成答案后自行宣布语义通过。
6. 工具轨迹、宿主回执和持久状态核对功能；原回答逐项对照来源核对语义。关键词命中、回答长度、标题、非空、completed 或测试全绿均不能自动打语义分。
7. 诚实说明“未知”“证据不足”可以通过相应事实边界检查。如果用户的目标没有完成，应另记“目标未完成”，不能把诚实拒判包装成研究能力已经通过。
8. 不存原始思考、密钥或原始上游错误正文。原始验收产物保存在忽略的 workspace/acceptance 下，失败记录不覆盖；文档只收录必要的脱敏摘要。

### 现有入口与本页的关系

scripts.eval_workspace 现有 direct、research、workspace、quality 四类场景。quality 已接入 [QF-1 适配器](../scripts/quality_fixtures.py)，通过本机 HTTP 执行 Q02、Q03、Q04 的四轮代表性输入：近期发现、方法比较、发表/数字核对、精简追问。它不覆盖八组全部输入、第二种表达、结果不足变体或浏览器交互，这些仍按下方卡片补验。

从仓库根目录运行默认离线模式：

~~~powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.eval_workspace --scenario quality
~~~

该命令使用合成模型和固定工具适配器，只验证 HTTP、会话、报告保存等管道。合成模型可能直接返回预置内容，不能据此证明自主选择工具、读取正文、发表核验或语义质量。report.json 的 semantic_review 为 not_applicable_offline_fixture；退出成功和 checks 通过不改变这个范围。

需要审阅真实模型时，先核实当前模型免费额度和服务可用性，再显式执行以下命令。这里的模型 ID 必须替换为本次已核实的值；示例不是已运行记录，也不自动解锁真实调用开关：

~~~powershell
$qualityModel = '替换为当前已核实免费额度的模型ID'
.\.venv\Scripts\python.exe -X utf8 -m scripts.eval_workspace --live --scenario quality --model $qualityModel --max-model-calls 24
~~~

--live 只改变模型调用，quality 的检索、正文和发表信息始终是虚构固定证据，不能称为真实论文检索。当前物理请求计数保护仅支持 Anthropic 兼容服务；不支持的服务会拒绝使用该 live runner。24 是共享请求尝试上限，不是云端零费用保证。真实模型输出的 semantic_review 保持 pending，须按本页人工核对。

quality 在独立验收进程中注入 registry.call_tool、dialogue.verify_publication，并冻结 dialogue/evidence 的当前时间；生产工具注册内容和用户服务不变。QF-1 的 query 文本不做领域路由或语义匹配，只提供固定候选及首次提交日期过滤/排序；正文可选精确的 method/experiment 节，其他查询返回两段有界正文并说明范围。未知 URL、网页或项目工具明确拒绝，无真实工具或网络回退。quality 拒绝 --live-search，也拒绝通过程序入口传入 search_mode=live。

每次默认创建新的 workspace/acceptance/<随机ID> 目录；也可用 --output-dir 指定尚不存在的目录，已有目录拒绝覆盖。产物包括：

- report.json：运行配置、轨迹、功能检查、待人工语义状态及 source_fixture.sha256。
- source-snapshot.json：冻结的 fixed_now、四条候选、A/B 文档与片段位置、发表观察。
- human-facts.json：独立人工核对依据，只写验收文件，不进入工具结果或模型上下文。
- web.db：该轮独立数据库，不使用真实 Web/CLI 用户库。

实现中 A 的发表观察为 publication_status=unresolved、peer_review_status=not_verified；B 为 publication_status=publication_record_found。它们分别对应下方“尚未核实”和“夹具内正式记录已确认”，不是质量排名。

现有 lodestar/fixtures.py 仍是旧占位管道数据，不能当 QF-1 或真实论文证据。若直接粘贴材料给模型，只能验收材料理解；真实公开论文场景需另建来源快照和人工事实表，不外推合成结果。

## Q06 · 个人共享、项目隔离与任务局部

**输入/操作**

**输入/操作**

1. “ReAct 我只看过思考和行动交替这个方法，没实现。记住这个接触情况，别算我掌握。”
2. “纠正刚才的接触程度：我其实只看到了摘要，没有认真学过，也没有实践。”
3. “我现在接触过哪些技术和方法？哪些还不能算掌握？”
4. “忘记刚才这条学习证据”，再问同样的问题；另用记忆中心撤销复核宿主路径。个人偏好另做修订/遗忘后追问。

**固定数据/准备**：新会话和空学习档案；ReAct 仅作为用户提供的方法/论文名称，不联网推断正文或补造 arXiv ID。Q05 后台运行不得预先生成相关学习事件。纠正和遗忘前后保存 ID、revision、事件类型、有效状态和实际消息来源。

**核对依据**：当前用户原话与 source_message_id；技术/方法关系、自评/接触记录和关联来源；撤销后的重新计算；history_after/实际后续上下文。后台材料、助手生成讲解或方案不是用户掌握依据。概念、组成、适用场景由模型组织，不是个人学习事实。

**失败判定**：记录“已学会/已实践/已验证掌握”；把派发研究当接触；存通用技术定义作个人记忆；纠正/撤销后仍自动用旧状态；引导用户接受虚假的“你已经熟悉”。遗忘不要求删除用户可见历史或备份，检查模型后续不自动重放失效事实。

## Q08 · 故障、取消、刷新与继续使用

**输入/操作**

依次在独立隔离实例执行以下故障，每项重置数据或记录继承关系：

1. 流已输出一段内容后，注入 data-only SSE error；再注入只有 ping 而无最终消息的空流。
2. 主空间成功提交一个子任务后，父运行流失败；刷新并重发相同 request_key，再查询任务。
3. 同时运行两个子任务，只停止其中一个；分别刷新两任务和主空间。
4. 运行中结束隔离服务，重启同一个隔离数据库；检查 interrupted，再发一条新的合法问题。

**固定数据/准备**：故障使用内存传输或测试适配器，不故意消耗真实额度制造错误；保留正常完成对照组。为鉴权、限流、超时等错误另用安全结构化类别夹具；错误正文加入合成 PRIVATE_CANARY，不能泄入 UI、日志或报告。启动耗时及取消等待按实际配置的超时核对，不凭空规定服务 SLA。

**核对依据**：部分回答、运行终态、实际 HTTP/模型尝试次数、动作回执、任务 ID/数量、活动运行集合、重启记录、后续问题。原 request_key 重发不新增动作；用户主动新请求不要求偷偷自动重试。data-only 错误与无消息流应分类区分，未知上游原因须保留未知。

**失败判定**：部分结果丢失；错误被显示完成；取消 A 误停 B；服务重启悄悄重放任务；刷新重复派发；父错误抹去已提交回执；无限等待；异常后无法继续；私密错误正文泄露；未经观测推断欠费/并发为根因。

**分别记录**

| 功能 | 语义 |
|---|---|
| 待执行：每种故障终态/耗时；部分产物；尝试次数；任务去重；恢复与泄漏检查 | 待执行或不适用：错误解释是否忠实；已提交/已完成区分；未知原因有无编造 |
