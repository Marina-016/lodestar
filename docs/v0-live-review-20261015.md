# V0 续检 · 2026-10-15

结论：任务约束交接与执行回执已补齐宿主机制；两轮真实 qwen3.5-flash 均实际提交两个任务。本次“空流”取得明确的传输证据并修复错误识别，但服务仍可能返回错误，术语理解与研究语义尚未通过整体验收。没有推送、部署、切换默认模型或修改真实用户库。

## 本轮修改

- create_task 增加必填 external_retrieval 与 constraints。约束只能是本轮用户消息中逐字出现的有界摘录；宿主附实际来源消息 ID 和父运行 ID。只交接任务指令与选中摘录，不复制主对话历史或未选中的当前消息。
- 禁止外部检索是子任务本轮的持久化运行策略：宿主隐藏并拒绝论文/Web 检索、阅读及发表核验。异常网关仍发出这些工具请求时也不执行；显式 research/plan 不能绕过。模型 API 本身和已授权的本地上下文仍可用，不能将其描述成完全离线。
- 模型仍负责选出适用约束、理解指代和设置策略。逐字校验证明来源，不证明摘录完整或语义正确；不是自然语言“不要联网”的确定性识别器。后续手动发给该任务的新消息不会自动沿用上次运行的权限。
- 任务提交、记忆保存/遗忘、学习反馈由宿主记录回执。UI 从回执显示实际操作，可打开对应任务；纯文字声称完成不会产生回执。已提交不等于任务完成；创建后启动失败记录为“已创建，未启动”；后续取消/模型出错不抹去已发生的动作。回执不保存记忆正文。
- 不重写模型回答或裁定其动作叙述的真假。正文仍可能与回执矛盾，回执是可核对的宿主事实，不是模型语义已修复的证明。UI 沿用白色布局，只增加轻量执行记录，没有新的报告模板。

## 本次空流根因与修复边界

带观测的失败请求返回 HTTP 200、text/event-stream、200 字节；只有 3 个 data.type=ping 和 1 个 data.type=error，没有 message_start/stop，也没有对应的 event: error 行。

本机已安装 Anthropic SDK 的流分支按 SSE 的 event 名处理错误。此次数据型错误未被识别，最终 get_final_message 因没有消息快照触发 AssertionError。这个案例是服务在流中报错，加上兼容层漏识别，不是模型没做工具决策，也不是已经证明的普通断网。

原流内错误的具体原因仍未知：未存储其正文，不推断为并发、额度、限流或模型故障。成功请求在相同配置下有完整 message_start/stop，也不能证明所有服务请求可靠。

providers/dialogue 在 SDK 公开 response.stream 上增加有界错误检查：识别 data-only 错误并返回 upstream_stream_error，不改变成功流字节、不读取/输出原始推理或错误正文、不重试或换模型。同块中先前已产生的文字仍先交给 SDK。保留原来的 stream_interrupted 处理，用于没有已识别错误的真正空/未完成流。

真实 SDK + 内存 SSE 已覆盖分片、多行、无末尾空行、同块部分文字和正常完成；每个用例只发起一次内存请求。该分类修复后未再调用真实服务，不宣称服务端错误已恢复。
