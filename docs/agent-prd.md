# Lodestar V0 · 产品逻辑与系统架构

更新：2026-10-15。V0 功能基线为 2026-10-11；本地增量包括重复请求保护、约束交接、动作回执及流内错误分类。本文描述当前实现与后续边界；功能证据见 [发布验收](v0-release-check.md)，最新真实证据与限制见 [10-15 验收](v0-live-review-20261015.md)。

当前质量分支的持续计划见 [V0质量版计划](v0-quality-plan-20261017.md)，实际修复、真实失败及授权上限见 [10-17续检](v0-quality-review-20261017.md)。模型自主决策的产品逻辑不变。read_task新增可取消的有界等待（默认10秒，0立即快照，最长20秒），只观察指定任务，不自动等待其他任务、汇总或重启。

## 1. 产品目标

帮助用户从最新论文中理解技术，结合自己的项目形成可验证的方案。信息来源优先论文；热门信号、官方网页与工程资料作为补充，明确来源与实际阅读范围。

掌握针对知识点、技术和方法，论文关系回答“接触过哪些论文中的哪些方法”。概念、组成和适用场景由 LLM 即时组织，不写成用户记忆。后台研究不意味着用户已读、已理解或已实践。

## 2. 三个入口

| 入口 | 作用 | 持久状态 |
|---|---|---|
| 主对话 | 日常交流、派发任务、按需汇总结果 | 稳定会话与个人记忆 |
| 任务 | 分别研究不同主题并查看各自进度 | 独立会话、来源、运行记录、模型设置、项目绑定 |
| 记忆 | 查看和纠正系统知道的个人与项目信息 | 带范围、修订和来源的事实；技术/方法学习证据 |

任务是同一位用户的工作分支，不是无痕身份。用户可以手动创建任务，也可要求主对话派发多个任务。任务不默认广播聊天记录；主对话按需读取具体任务结果。V0 不实现选中历史消息分叉或独立无痕模式。

## 3. 系统架构与一次运行

~~~text
Web UI（主对话 / 任务 / 记忆）
   ↓ 同源请求 + 页面 token
WebApp（共享用户、任务归属、运行及持久化）
   ↓ 当前会话历史 + 有界记忆 + 项目 ID + 冻结模型配置
ConversationAgent
   ↓
dialogue.gather：模型决定回答、检索、阅读、调用宿主工具
   ↔ 论文/网页工具、任务工具、记忆工具
   ↓
自然回答、来源及实际记忆快照 → SQLite → 流式 UI
~~~

运行步骤：

1. 校验任务、重复提交标识、调用开关和当前运行状态；冻结模型配置。
2. 载入当前任务近期消息及其上下文边界。个人/当前项目/当前任务记忆先按宿主范围过滤，再按词法匹配和近期顺序选择，有 8000 字符、20 条的注入上限。
3. 模型自主决定直接回答、澄清、搜索、阅读、派发任务或更新明确事实；没有固定对话阶段或关键词路由。
4. 每个工具结果保留来源/范围/错误。普通工具共用操作预算，并保留最终回答调用。
5. 保存回答、引用与检索记录、实际使用的记忆 ID/revision、项目和运行配置；后台研究不自动产生用户接触记录。
6. 浏览器显示增量文字与状态。刷新恢复持久记录；服务重启将未完成运行标为 interrupted，不自动重跑。

运行生命周期为 queued → running → completed/error；停止为 cancelling → cancelled。这是任务执行状态，不是限制模型意图的对话状态机。同任务串行，不同任务可并行。停止主对话不会停止已经派发的子任务，子任务各自停止。

## 4. 模型可用工具

| 工具 | 用途与边界 |
|---|---|
| search_papers / discover_papers | arXiv 检索、近期与 HF 热门发现；保留日期和渠道 |
| read_paper | 有界论文阅读，区分摘要、正文片段和失败 |
| verify_paper | 核对发表信息；未知不等于未发表 |
| project_context | 读取绑定项目内明确授权外发的有界材料 |
| search_web / read_webpage | 补充官方网页与工程资料；失败不能冒充成功 |
| read_memory | 按需读取当前允许的事实及学习证据，有界返回 |
| manage_memory | 保存用户提供的事实/偏好或确认的项目决定，按 ID 纠正/遗忘 |
| record_learning | 前台用户讨论、尝试和自评；宿主附实际用户消息作为证据，不提供 demonstrated 掌握事件 |
| list_tasks / read_task | 先看任务状态，再按需读指定结果及来源，不自动装入所有聊天 |
| create_task | 仅主对话可派发；子任务继承模型设置及默认项目，防止递归派发 |

派发指令附选中的本轮用户原话约束及来源 ID，不自动复制主对话历史。模型负责选择适用约束和设置 external_retrieval；策略为 blocked 时，宿主拒绝子任务本轮的外部检索/读取/发表核验，不关闭模型 API 或扩大本地资料授权。摘录校验不证明语义完整，后续手动新消息不自动继承上一轮策略。

任务提交和记忆操作另有宿主执行回执，不从模型正文推断。回执可打开实际任务；已提交不等于完成，创建后启动失败单独记录。回执不保存记忆正文，后续模型出错或取消不会抹去已发生的动作；正文仍可能与回执矛盾，不能据此宣称自动调度语义已稳定。

具体研究工具名称以 registry 与 dialogue 中的定义为准。后台子任务不开放 record_learning，不能创建、迁移、修改或遗忘个人记忆；可保存任务/项目研究事实。自动 exposure 抽取也在后台关闭，后续用户进入任务实际讨论时按前台规则处理。

## 5. 记忆维护

| 对象 | 内容 | 谁可以使用 |
|---|---|---|
| 个人事实 | 用户偏好与明确提供的持久事实 | 同用户所有任务 |
| 项目事实 | 已确认的项目目标、约束、决定 | 绑定同一项目的任务 |
| 任务备注 | 局部研究状态或工作事实 | 当前任务 |
| 学习证据 | 技术/方法、接触、自评、表现来源和关联论文 | 同用户；与普通事实分别管理 |
| 研究资料 | 论文、阅读证据和方案/实验产物 | 按任务/项目及显式交接使用 |

Web 使用稳定用户 web:local。个人事实不是其他任务的完整对话摘要。模型工具只访问当前允许范围；用户的记忆中心可管理自己的所有范围。项目登记只存元数据，不自动索引或外发仓库。

记忆有 active/disabled、revision 和来源消息。编辑需匹配 UI 读取的 revision，避免旧表单覆盖新内容。相关任务仍运行时，跨任务共享记忆修改返回冲突，等待结束或停止后再改。

纠正、停用或遗忘会推进受影响任务的 history_after 边界并清空旧证据缓存；当前工具轮次也清理旧模型上下文和保留回答通路中的旧操作结果。聊天显示不删除，但模型不自动重放旧段落。此保守处理会损失部分连续上下文，用户可重新提供仍有效的条件。遗忘清空该事实的修订正文；不承诺删除历史聊天、备份或撤回服务商已接收信息。

学习纠正保存为 self_report，并撤销旧事件后重新计算；手工操作不生成已验证掌握。后台读论文和助手生成方案不作为用户学习证据。自动学习表现判卷仍未实现。

## 6. 旧数据升级

只迁移 Web 自有数据，不合并旧 CLI 数据。保留 task/conversation/message/learning ID：

- 旧逐任务用户键映射到同一稳定用户。
- 主空间原备注成为个人范围；旧任务原备注保留任务范围。
- 用一次性迁移标识避免重复导入；遗忘同步清理旧备注副本。
- 迁移前使用 SQLite backup API 备份；在副本上核对数量、归属和完整性。

## 7. 研究到方案与实验

已有独立后端链路：

项目登记/有界索引 → 公开 query 订阅发现 → 阅读/证据交接 → 适用性评估 → draft 方案 → 显式实验与评分。

propose_change、investigate、no_change 分别对应实现建议、继续调查和无需修改，不能为生成方案虚构缺陷。实现型 A/B 需要冻结输入、实现和独立评分；调查型实验有独立协议与关联记录。网页聊天不自动执行代码、批准方案或部署。

“最新”按检索返回的首次提交日期及用户时间范围解释，更新不等于新发表；“热门”是渠道信号。引用存在、正文片段与测试通过都不等于语义事实已核实。既有质量缺口见 [harness 记录](dialogue-harness.md) 与 [历史后端台账](agent-goal-audit-20261008.md)。

## 8. 费用、数据与服务边界

支持已配置的模型服务，同服务切模型及原生推理参数，不自动跨服务或付费回退。示例关闭真实调用；代码配置的默认值并非全局禁费保证。免费额度必须当前核实，历史核对不构成当前额度。

官方阿里搜索 MCP 为可选后端，需核实、登记剩余免费次数，持久化预约防并发超用；不能代替云端账单控制。公共引擎被验证拦截时明确返回失败。

用户明确授权外发的 Lodestar 代码仍限 memory/learning.py、retrieval.py、agent/project_plan.py 的有界片段；项目绑定、共享记忆和本次上线准备不扩大整仓库授权。

服务仅绑定 127.0.0.1，写请求检查 Host、Origin 和页面 token。没有公网认证或多租户隔离，不能将本地 owner 字段当成账号系统。

## 9. 交付与后续

V0 已实现主对话、自然语言任务派发、分开进度与对话、共享个人身份、项目范围、可管理记忆及学习证据、取消恢复和来源检查。

后续优先：真实模型/论文质量回归、可靠通用搜索、长期历史召回、持久后台与通知、公网认证/隔离/HTTPS/备份/限流。选段分叉、无痕模式、自动掌握判卷和方案自动采用不属于当前交付。

10-14 已使用用户指定的免费 qwen3.5-flash 验证部分真实通路，但自动派发、子任务约束交接、空流及研究语义仍有失败。模型说“已派发”不代表任务真的存在，来源状态 not_verified 不代表尚未发表；这些不是已通过的质量能力。

10-15 两轮真实验收均实际提交两任务并保存禁止检索策略；整轮仍因子任务错误未完成。本次空流观察到服务以 HTTP 200 返回 data.type=error、没有消息事件，SDK 漏识别后触发断言；兼容处理已用真实 SDK 内存流验证，不代表服务端错误恢复。Harness 术语理解仍偏离项目意图，研究语义继续待验收。
