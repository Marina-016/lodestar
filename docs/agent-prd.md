# Lodestar PRD：单入口、按需独立任务与可管理记忆

产品方向更新：2026-10-10。实现核对基线：`5382412`。本文是当前产品定义，明确区分“已有实现”和“规划”；本次只修订文档，不表示新前端、任务隔离或记忆管理已交付。

实现见 [系统架构](agent-architecture.md)，排期见 [当前计划](agent-long-term-plan.md)，现有入口见 [对话用法](chat-usage.md)。历史验收保留在 [2026-10-08 台账](agent-goal-audit-20261008.md) 等原记录中，不改写失败结果。

## 1. 产品决策与旧版修订

用户明确的方向：

- 默认只有一个连续输入入口，不要求先创建或选择一条聊天。
- 不增加“个人助理”人设，也不扩展成通用生活助理；核心仍是研究、理解、项目关联和验证。
- 用户需要分离时，显式创建两个或更多独立任务；不能只是视觉上分栏、实际共享一份上下文。
- 记忆是可查看、编辑、限定范围、停用和删除的产品对象，不是隐藏的无限聊天历史。
- 前端以简洁白色系为主，模型选择、深度思考、来源检查仍可直接使用。

本评估建议采用“默认主空间 + 显式独立任务 + 分范围记忆”。以下默认策略为本版设计建议，尚待实现与验收，不是现有能力声明。

| 旧 PRD 描述 | 核对结果与本版处理 |
|---|---|
| 普通消息先保守意图路由 | 已过时。`auto` 使用原生模型工具循环；research / plan / feedback 是显式 API 选择 |
| 追问最多补读两篇 | 对普通对话已过时。其搜索、读取、核验共享默认 8 次操作；显式 plan 的既有补读仍最多两篇 |
| 固定结构化讲解 / 分栏 | 已过时。普通回答自然输出 Markdown；独立方法接触提取和方案契约仍有校验 |
| 只有特定免费模型、没有交互设置 | 不能作为当前产品总描述。已有同服务模型切换、档位和思考模式；历史额度及外发许可不能沿用为新授权 |
| 147 项回归代表当前版本 | 是 10-08 历史结果。10-10 最近记录为 254 项离线通过，不代表事实性或新功能验收 |
| 前端一直暂缓 | 改为下一阶段的产品计划；目前旧 UI / 在线回放仍未接入新对话能力 |

## 2. 目标与非目标

面向 AI 从业者，允许从一个自然问题开始，连续研究、解释、比较、改写或讨论项目。用户不必记住信息在哪条聊天里；需要隔离目标、资料或上下文时，由用户主动分离任务。论文/Web 检索、项目关联、技术草案和实验仍是可组合能力，而不是每个问题必经的流程。

本期不做：助理人设、自动把每次话题切换建成任务、多 Agent 编排、无限上下文、自动执行代码、永久后台通知、多用户云端认证，以及“模型说过就永久记住”。白色 UI 或单入口不等于模型事实性、洞察深度已经达标。

## 4. 目标交互：默认连续，分离显式

### 4.1 默认主空间

用户打开即输入，不先点“新建聊天”。主空间按本地用户持久化，刷新或正常重启恢复；话题变化不自动新建任务、不自动切换项目。历史可以按时间浏览和搜索，但不作为首页的主要导航。

连续体验不等于每轮加载全部历史。最近消息之外，按需检索可用历史或读取有来源的状态摘要；找不到“上次那个方案”时说明缺口，多个候选时简短澄清。单入口不承诺任意久远内容都能无误回忆。

### 4.2 两种显式分离

| 操作 | 起点和继承规则 |
|---|---|
| 新建独立任务 | 空白任务；不带主空间或其他任务的消息、证据、摘要、项目绑定和未确认记忆。只可使用用户已允许的全局记忆，创建时可关闭 |
| 从这里分离 | 用户选定消息/成果后预览，将选中内容及明确列出的来源快照带入新任务；原内容不搬走、不删除，不继承未选择的整段历史 |

两种操作都显示任务名、携带资料、记忆范围和可选项目；不能用相同按钮隐藏不同继承语义。可以保留 A/B 两个任务并切换或打开两个视图，不要求两个任务必须并发执行。

用户输入“这件事单独开一个任务”与点击分离具有同等效力；执行前确定空白/选段及范围，不要求用户学习命令。模型可以建议分离，但不能仅因检测到新话题而自行创建。任务支持重命名、完成、归档与恢复；归档不等于删除历史或把任务记忆公开。

分离后原任务与新任务各自推进；记录来源关系不代表可读取父任务后续内容。跨任务引用通过用户明确选择的内容快照进行，不自动合并双方状态或共享后续修改。

### 4.3 上下文与权限边界

| 对象 | 默认主空间 | 独立任务 A / B |
|---|---|---|
| 最近消息、检索候选、已读证据、任务摘要 | 仅主空间自身 | 各自拥有，不自动串用 |
| 全局记忆 | 用户已确认且启用的条目 | 同样只取已授权条目；每任务可关闭 |
| 项目资料和项目记忆 | 显式选择项目并满足权限后使用 | 仅所绑定且授权的项目；同项目不意味着共享另一任务的私有历史 |
| 任务记忆与暂存判断 | 留在本空间 | 仅本任务；不自动升级为项目或全局记忆 |
| 显式带入内容 | 保留来源 ID、版本和选择范围 | 只读入选定快照；外发仍校验原资料许可 |
| 模型与思考设置 | 主空间设置 | 新建时可复制设置值，之后独立；切换 A 不修改正在运行的 B |

“独立任务”默认隔离任务上下文，不代表禁用用户允许的全局记忆。界面必须显示这一区别；关闭全局记忆也不能绕过项目授权。主空间搜索默认不返回独立任务私有历史，跨任务搜索要显式选定范围。

## 5. 记忆作为可管理对象

### 5.1 分类与范围

统一管理入口区分：用户偏好/用户确认事实、项目记忆、任务判断/状态、研究知识与来源、学习事件。统一界面不要求把它们改成一张表，也不混淆证据与结论。

- 权限维度为 owner + scope（global / project / task）+ scope_id；无明确归属的旧记录不能默认全局可见。
- 原始消息是历史，论文片段是证据，状态摘要是压缩视图；都不自动变成已确认长期事实。
- 任务暂存和模型建议只在本范围使用。普通学习接触可继续记录为 explained，但新任务路径必须补范围，不能沿用现有 user 级召回而串任务。
- 用户明确要求记住具体内容，可保存到显示的范围并回执；模型自行提议的新增/改写先待确认。扩大到项目或全局范围需要用户明确同意。
- 项目中的私有事实即使被保存为记忆，也仍受资料外发许可约束；用户查看权限与向远端模型发送权限分开校验。

### 5.2 首版管理能力

支持列表、搜索、按类型/范围/状态筛选、查看原始依据、新增、编辑、停用/恢复、删除和本地导出。每条展示内容、范围、来源、更新时间、确认状态，以及本轮是否被使用。首版不做记忆图谱和全量聊天自动“人格提炼”。

建议最小元数据：`id / owner / kind / scope / scope_id / content_or_ref / status / revision / provenance / created_at / updated_at`。保留现有学习事件与掌握计算规则；人工编辑普通记忆不能伪造 demonstrated 类学习证据。

状态区分 pending、active、disabled、superseded、deleted；编辑生成新 revision，冲突项标注待确认，不用“最新一次模型判断”静默覆盖用户确认内容。记忆写操作走显式 API/确认，不把任意网页里的指令当作写入授权。

### 5.3 停用、纠正与删除的实际语义

- 停用：下一轮新上下文不自动召回；已打开的历史仍可查看。不能只从列表隐藏，而在历史、缓存或摘要里继续当作当前有效事实使用。
- 纠正：新 revision 替代旧结论，引用旧版本的状态摘要失效或重建；旧版本只用于明确的历史审查，不再默认注入模型。
- 删除：确认界面说明删除的是记忆条目，还是还包括其关联的历史/产物。删除记忆条目需清除本条及其旧版本的可召回内容与派生索引/缓存，仅保留不含原文的最小审计标记；不默默删除论文或原始聊天。
- 若用户要“不要再使用这件事”，还需排除关联历史片段和派生摘要；否则旧消息可能重新引入它。以来源关联和上下文载荷检查验证，不能承诺模型凭自身知识也绝不提及同类信息。
- 当前运行已外发的信息无法撤回；普通停用明确下一轮生效，撤销资料访问权限则阻止后续调用并中止相关运行。物理清除本地历史、备份或已导出文件是另一个明确范围的操作，不承诺外部服务同步遗忘。

本轮可展示记忆/历史引用 ID 与选择原因，不展示或保存原始内部思考文本。

## 6. 可行性与最小技术方案（规划）

结论：可行，复用当前 Python + SQLite + 原生工具循环，整体复杂度中等偏高。主要工作在持久化状态、上下文隔离、记忆失效与旧数据迁移，不需要另建一个“助理 Agent”。

```text
固定输入入口 → 当前主空间 / 显式任务 → 宿主过滤权限与组装有界上下文
                                      ↓
                              现有原生工具循环
                                      ↓
                         本次运行、回答、证据与产物
```

### 6.1 复用和新增

| 层 | 建议实现 | 复杂度 |
|---|---|---|
| 实时 Web 接口 | 复用 ConversationAgent 与 on_text/on_progress，提供带 run ID 的事件流、最终态和错误态；旧回放明确另入口 | 中 |
| 主空间与任务 | 新增稳定 work_item（含默认主空间、owner、project、status）；关联现有 conversation，而非把一次 research_task 当长期任务 | 中 |
| 单次运行 | 统一 run 引用一次回合/研究执行，保存工作项、输入 ID、配置/范围/版本快照、结果状态；适配现有 research_tasks 和 Trace | 中 |
| 上下文与历史 | 先按 owner/task/许可过滤，再做 SQLite/FTS 候选检索；有需要才提供 search_history/read_history 小工具 | 中；中文词法/别名召回有局限 |
| 记忆管理 | 现有概念/学习仓储加范围与管理适配；新增通用条目和版本/来源关联；停用、删除同步使派生摘要失效 | 中高 |
| 新前端 | 从嵌入 ui.py 的历史页面分离 UI 资源；连续主区、任务切换、记忆抽屉、证据与配置控件 | 中 |

先过滤再检索，不能全库检索后仅让模型“不要看别的任务”。旧消息、摘要、候选来源、全局学习事件、项目事实都必须经过相同范围规则。只读工具与现有操作预算组合，不增加强制规划/反思阶段，不维护术语白名单；约束的是数据作用域和操作权限，不规定模型研究策略或回答模板。

任务/记忆管理由应用服务提供小型显式操作，与只读研究工具分开。自然语言可以生成创建、分离或记忆修改建议，但实际写入须对应用户明确指令或界面确认；不再增加一个强制意图分类模型，也不让检索材料成为写入授权。

第一版不依赖向量库：恢复当前状态、准确范围和显式历史查询先可用；自然语言跨时段召回须单独评测，词法基线达不到需求后再考虑 embedding。摘要携带原消息/来源 ID、时间、revision、未决项和“模型总结”标记，不是核实事实；压缩产生的额外调用需计入预算，失败不覆盖原文或有效快照。

### 6.2 并发、恢复和迁移

- 每次发送先固定 work_item/run ID 与配置、记忆版本、权限范围；刷新、切任务或改模型不能让事件写入另一个任务。
- 固定快照不是永久授权：后续工具/模型调用仍检查删除或资料权限撤销；相关条目被删除或访问被撤销时，中止受影响的后续调用，不能继续使用旧快照。已外发数据仍无法撤回。
- 同一任务首版串行处理，重复提交用幂等键；不同任务可独立排队。真正并发执行、跨窗口同步控制不是“两任务可独立存在”的前提。
- 流式断开不等于任务取消；取消有明确状态。晚到事件不能覆盖新运行；重启后中断状态需标明，重试由用户触发，不自动重复付费或执行有副作用动作。
- 迁移采用新增实体/字段与兼容适配，先备份并在副本验证，不重写或清空用户库。旧会话保留为可访问的历史项；用户选择主空间，不能自动合并所有历史。
- 现有无 owner 的知识/项目、user 级学习事件先明确归属和适用范围；无法确定的条目放待归类区，不因迁移变成全局记忆。
- 首版限定本地单用户；所有新查询仍带 owner 校验。云端认证、租户隔离、备份清除和联网部署另立验收，不能拿本地 user_id 当安全认证。

## 7. 简洁白色 UI 的信息结构（规划）

默认进入主空间；窄侧栏只保留主空间、显式任务、项目和记忆入口，不以一列“新建聊天”作为主体。主区连续阅读和输入，顶部轻量显示当前范围；任务可切换或打开独立视图，证据/记忆按需展开。主空间不会因展示多个任务进度而自动获得它们的私有内容。

视觉约束：主背景 `#FFFFFF`、侧栏 `#F7F8FA`、正文 `#20242A`、辅助文字 `#6B7280`、分隔线 `#E5E7EB`、强调色 `#4F6BD8`。界面/正文使用系统无衬线中文字体，代码/引用 ID 使用等宽字体；正文约 16px、行高 1.8、阅读宽约 760px，移动端按可用宽度适配。减少嵌套卡片、渐变、统计装饰和固定报告标题。

辨识点放在“当前上下文”入口：可检查本轮带入了哪些任务资料、记忆与来源。模型/档位/思考控件邻近输入框；请求配置与服务实际支持情况分开显示，失败不静默换模型。所有折叠/范围控件可用键盘操作，选中态不只依赖颜色。

## 8. 分期、复杂度与工作量估算

以下为基于现有代码的一名单人全职开发者的粗估，不是承诺工期；每阶段包含针对性测试，最终联调另列。假设沿用本地 Python/SQLite、轻量 Web 前端和已有模型接口，不同时重写研究流水线。

| 阶段 | 交付与依赖 | 粗估人日 |
|---|---|---|
| P1 单入口实时基础 | 前端拆分、现有后端事件流、模型/思考控件、owner 与默认会话指针支持主空间恢复 | 3–5 |
| P2 显式独立任务 | work_item/run、空白与选段分离、各自状态/配置、幂等与恢复、旧会话兼容；依赖 P1 接口 | 4–7 |
| P3 可管理记忆与有界召回 | 范围/版本/来源、CRUD、停用删除与摘要失效、历史查询、旧记录归类；依赖 P2 的范围模型 | 5–8 |
| P4 联调与产品验收 | 长历史、重启、双窗口、隔离/撤销/错误态、响应式及同证据回答审核 | 3–5 |

合计约 15–25 人日，即单人约 3–5 个工作周。只做白色壳层较快，但不能宣称实现“打破会话边界”。不含向量/语义检索优化、多用户云服务、长期后台、语音、完整历史清洗和研究质量的开放式优化；旧数据脏污或兼容网关差异可能扩大估算。

P1 可以内部试用，但只达到入口与实时通路；P2/P3 隔离与记忆验收通过后，才可对外描述完整的新交互。研究质量作为并行质量门，不以这套 UI 发布代替事实性验收。

## 9. 验收标准（新方向，尚未执行）

| 场景 | 必须检查的结果 |

| 长历史与插话 | 超过近期上下文预算后，能找回已明确保存的方案/来源；无结果或歧义如实提示，不靠无限拼接历史 |
| 两个空白任务 | A 的私有金丝雀消息、来源、暂存记忆不进入 B 的检索候选、摘要或模型请求，主空间也不能默认查到 |
| 从这里分离 | 只携带预览确认的消息和证据快照；父任务后续修改不串入，历史和原产物不丢失 |
| 全局/项目记忆 | 仅确认且授权范围内可召回；任务关闭全局记忆后不注入，选项目不扩大代码外发白名单 |
| 停用/纠正/删除 | 新轮次排除失效条目及受影响摘要；“不要再用”还能排除关联历史；明确说明留存和删除范围 |

## 附录 A：保留的研究链路与契约（已有实现）

普通交互：用户消息 → 原生工具对话 → 自然回答 / 按需检索、阅读、核验 → 保存回答与来源。默认共享 8 次只读工具操作预算，另保留一次回答调用；`research / plan / feedback` 仅由显式接口选择。没有普通对话专用 JSON 动作规划、关键词路由或固定补读篇数。

主动发现：登记并索引项目 → 配置公开 query 和本地 term → watch tick/worker → 本地筛选 → inbox。发现和阅读不调用模型。到期轮询有租约、错误与重试记录；需要运行进程，尚未安装永久后台服务或推送通知。

候选研究：read → evidence / handoff → assess → plan → 按动作分支。handoff 将已读证据交给绑定项目的会话。评估和方案满足模型开关及精确项目文件外发授权；复用评估的阅读与项目证据快照，证据变化要求重新评估。

“最新”以检索实际返回的首次提交日期和窗口为准；按 submittedDate 搜索且未指定 days 默认最近 90 天，discover recent 默认 7 天。用户明确时间范围优先；更新日期不等于新发表。“热门”是 HF daily papers 的平台信号，不代表全网热度。项目订阅 query/term 由调用者配置，普通模型可自主拆查询；本地项目/学习召回仍是词法检索。未核验发表不等于未发表，发表记录也不等于权威。

### 方案动作与失败状态

propose_change：需要 1–3 项有依据的改动，可在审核实现和固定协议后显式运行成对实验。investigate：需要明确调查理由，改动列表为空，可以运行独立诊断并登记结果。no_change：需要有据理由，改动列表为空，停止改动路径。不能为了生成改动而虚构缺陷；调查或无需改动草案不能启动实现型 A/B。

model_disabled、needs_export_scope、needs_assessment、needs_reassessment、needs_live_assessment 表示门禁或缺口，不是成功方案。mock/test 评估不能直接成为 live 方案依据。候选 URL 与阅读记录 URL 必须一致；版本更新不能复用旧版正文，新版读取失败也不能用旧版充当当前证据。无版本 URL 的内容变化仍需要显式刷新。

引用校验只证明指定文本存在，不证明迁移合理。模型或工具失败保留错误和已有证据；综合失败后可复用 read_evidence.json。实验执行、实验判定、人工语义审核和采用状态独立，均不自动提升用户掌握。

普通追问和论文导读使用 conversation 模型直接输出 Markdown。检索提供完整摘要，模型决定介绍、比较和建议的表达方式；不再逐段分类、强制逐字引文或用链接列表替换回答。模型注明摘要与正文的阅读范围，普通回答不是已自动核实的研究结论。方法接触的提取独立运行，仍要求来源原文与已送达讲解双重匹配，不自动升级掌握；项目技术方案与实验契约保持独立。

### 当前两种记忆的维护（不等于已实现第 5 节）

研究知识库存论文、研究笔记和可复用来源证据；学习事件库存 user、technology、method、paper URL、事件来源与表现证据。掌握针对知识点、技术或方法，不针对论文；论文关系用于回答接触过哪些文章中的哪些方法。

概念定义、组成、适用场景由 LLM 组织，不写成个人学习事实。讲解只产生 explained 接触事件，且必须同时找到原文和本次讲解中的引用。懂了是 self_report；示范类掌握依据要求调用方核验，自动表现判卷未实现。撤销后根据完整有效历史重新计算。追问的提取审计附在回答元数据中，不作为新对话消息送回模型。上下文实验只修改临时研究状态，不修改来源记录或用户学习库。
