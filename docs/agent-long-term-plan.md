## 下一阶段：单入口与可控边界

| 顺序 | 交付 | 粗估人日 |
|---|---|---|
| P1 | 白色简洁主区、Web 实时接口、模型/思考控件、默认主空间恢复 | 3–5 |
| P2 | 稳定任务/运行实体、空白独立任务与选段分离、各自上下文和设置、幂等与迁移适配 | 4–7 |
| P3 | 记忆范围/版本/来源、管理界面、停用删除和派生状态失效、范围内历史召回 | 5–8 |
| P4 | 长历史、双任务、重启/断流/取消、金丝雀隔离与旧数据迁移验收 | 3–5 |

合计粗估 15–25 人日，单人全职约 3–5 个工作周，非工期承诺；假设复用 Python/SQLite 和现有模型接口，不含云端多用户、向量召回、后台服务或开放式模型质量优化。具体依赖、范围和验收见 PRD 第 4–9 节。

不自动按话题建任务、不把全部历史灌入上下文、不把任务记忆自动升全局。首版不引入多 Agent 或向量库。两个任务可独立存在不等于必须同时运行；真正并发和跨窗口控制后续按需求增加。

## 并行质量门与后续扩展

同模型/同证据先检查 harness，再分别比较模型/思考。建立独立研究问题、来源语义标注和人工质量审核；不以字数、标题、非空、绿色测试或新 UI 当质量证明。单入口与记忆改善连续性，不自动解决事实性和洞察问题。

后续另行评估：自然语言/别名语义召回、代表性项目重复实验、持久后台/通知、自动表现判卷、多用户云端认证。采用决策、方法收益与用户掌握继续分开，不自动运行模型生成的代码。
