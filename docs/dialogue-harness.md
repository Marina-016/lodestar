# 简单的对话 Harness

2026-10-10：普通对话改为连续的原生工具调用，不再分成 JSON 动作规划和独立回答生成两个阶段。

## 当前运行方式

用户消息、历史、已保存的来源和当前时间进入连续对话。
模型可以直接回答，也可以调用只读工具；工具结果携带原生 call ID 回到同一对话，
模型根据实际结果继续检索、读取或回答。没有研究步骤模板或关键词路由。
宽泛方向是否拆解、用什么查询、是否换来源，由模型决定，不维护 AI4AI 等术语映射表。

职责分为四层：

- dialogue.py：对话循环、只读工具边界、调用预算、来源保存。
- providers/dialogue.py：Anthropic 原生消息与 DashScope/OpenAI 工具消息、文字流式传输。
- conversation.py：用户与项目隔离、会话持久化、显式工作流和独立学习记录。
- evidence.py：来源事实合并、发表查询状态、去重后的回答证据包；不判断研究质量。

论文检索接受 query 或 queries（1–3 个独立查询）。每个查询保留原有 AND/显式
arXiv 语法；不把不同方向自动拼在一起。工具分别检索、交错合并、按论文去重，
保留 matched_queries、各查询命中数及失败原因，部分失败不会丢掉其他查询的证据。

已删除旧 explanation.py 回答生成阶段，以及 dialogue_step 专属 JSON schema、
JSON 动作修复和基于关键词的离线规划夹具。显式 research/plan 等结构化工作流仍用
通用 complete_json，不受普通聊天精简影响。

## 保留的边界

- 普通回合的检索/读取/发表核验共用预算，默认 8 次，可用
  LODESTAR_DIALOGUE_MAX_OPERATIONS 配置为 1–20；批量查询分别计数。
  批次超过剩余额度时仅执行可容纳的查询，并明确返回 skipped_queries。
- 检索预算之外保留一次回答调用；向其提交原问题、历史和已获取证据，关闭工具。
  原生工具调用块不再传入这次调用，避免兼容网关沿用旧工具而无法收尾。
  如果网关仍返回工具请求或空回答，交付明确标为尚未核验的候选链接或证据缺失说明；
  不额外执行检索。传输失败仍保存证据和部分回答，并报告错误。
- 只暴露论文/Web 检索、发现、读取、发表核验及已绑定项目的查询，不开放写入或执行。
- 读取仅允许已返回的来源链接；项目读取继续执行原有外发授权。
- 参数不合法返回工具错误供模型自行修正，不另起 JSON 修复模型调用。
- 保留完整摘要、阅读深度、检索失败与空结果的区别；失败阅读不覆盖已有正文。
- 工具记录、候选和已读证据可恢复；流式中断保留部分文字并标记未完成，不重放。
- 工具调用前的文字属于过程输出；持久化的正常回答及学习接触校验使用最终文字。
- 学习接触记录独立校验已读来源与送达回答，不自动提升用户掌握程度。

普通回答没有强制标题、表格或引文块；contract_valid 只表示非空文本，不表示事实
准确性、论文权威性或用户指令遵循已通过验证。mock 模式仅返回明确标识的离线夹具。

## 验证与已知限制

原生消息与 ID 配对、多调用预算、未授权 URL、项目范围、流式截断、会话恢复、
完整摘要保留、学习记录，以及显式研究/方案工作流均有离线回归测试。
Anthropic 兼容服务做了真实多轮测试；DashScope 的原生工具流仅做模拟协议测试。
此前全量运行 232 项全部通过；新增模型控制的验收见文末。

前一轮真实多轮输入依次为“目前在ai4ai方面 有什么最新的权威论文”、
“agent方向呢 有哪些论文？只推荐两篇。”、“不用检索，用两句话解释刚才的方向，不要标题。”：
三轮均完成回答。原问题在 5 次操作后由预留的回答调用完成；Agent 追问提交了 3 个
独立查询，合并返回 11 篇候选，最终选出两篇；最后一轮未检索并按两句话解释。
但 AI4AI 推荐混入 2020 年综述，且把综述全面性当作权威性依据；最新性、相关性、
引用支持程度及发表状态核验未通过质量验收。修复了检索组合能力与预算收尾，
不能据此宣称研究回答质量已经达标。

### 时间与发表证据修复（2026-10-10）

按 submittedDate 排序且未指定 days 时，检索默认限制最近 90 天；days=0
明确取消时间限制。结果报告实际时间窗口和首次提交日期依据，更新日期不能替代
首次提交日期。其他排序不自动限制日期；用户明确指定的范围优先于参考窗口。
普通对话新增 verify_paper，可对已返回的论文链接按需复用 venue 查询，计一次操作。
发表记录、同行评审与权威性分别处理；查询失败或未检查均保留未知状态。
阅读论文时保留检索日期与发表元数据，避免覆盖已有证据。

真实 AI4AI 检索推荐的四篇候选均在近 90 天内；固定 2020/2024 年候选回放
没有再将它们推荐为最新论文。但质量验收仍未全部通过：模型在没有执行发表核验时，
仍会把 not_checked/not_verified 错说成“未发表/未经同行评审”，即使提示已明确区分。
固定证据回放也出现“首次提交或更新”的错误概括，并把顶会接收简单等同权威性。
这些输出错误不能单凭一次回放归因于模型；当时的 harness 仍有证据传递、发表查询
和预算分配缺陷。不能以非空回答或离线测试通过代替质量验收。

### Harness 再审与修复（保持当前模型及推理配置）

- 删除伪造的 assistant 确认消息；当前来源状态放在历史之后。回答收尾只传一份
  合并证据与简短操作摘要，不再重复灌入每次工具返回、全文和旧回答。
- 重复检索、阅读、查询失败不能清掉已有日期、正文和确认的发表记录。
  候选池从 12 扩到 32，覆盖默认预算下全部检索结果，避免后续宽泛查询挤掉早期候选。
  未检查、查询未确定、只找到预印本、找到发表记录分别报告，不把状态计数当质量分。
- 读取论文自动附带可用发表查询结果（沿用 enrich_venues 开关），也可单独 verify_paper。
  15 分钟内复用查询，避免失败结果永久缓存；全文阅读支持模型提供论文语言的查询词，
  不再强行用中文用户消息筛选英文正文。已知 arXiv 链接的无版本引用可安全解析。
- venue 查询不在预印本记录处提前停止。Semantic Scholar 不再把任意 publicationTypes
  当成正式发表；题名匹配阈值收紧到 0.95，身份匹配优先于“已发表”偏好。
  OpenAlex 改为保守题名匹配并检查全部 locations，仓库位置不能覆盖同名发表版本。
  接口字段依据：[OpenAlex works 属性](https://help.openalex.org/data/works/attributes/)。
- 发表来源的限流、请求失败、空结果与记录分别报告。普通对话不做后台重复重试，
  请求超时参数设为最多 3 秒；限流冷却 60 秒，其他失败冷却 15 秒。返回出版页链接可继续读取。
- 对话传输尊重 llm_thinking 开关，不再硬编码禁用；本次没有更改实际开关或切换模型。
  网页阅读保留页面声明的发表时间，区别于检索时间。

同模型真实多轮中，原问题会自主组合查询、Web 搜索和发表核验；两句话、不搜索的
解释要求可正常完成。单篇读取验收也能在同一次工具结果中拿到摘要与发表查询状态。
实际查询发现 Semantic Scholar 限流、DBLP 响应无法解析，OpenAlex 有时只返回仓库
位置；这些都不是论文未发表的证据。论文推荐仍偶有“仅以预印本存在”“可能仍在审稿”
等超出证据的措辞，完整事实性验收尚未通过，不能宣称权威判断已经稳定。
最后一次原问题复测也出现 AI for Science/数据集等相邻方向混入推荐，故相关性仍需
后续质量验收；没有用主题白名单、关键词路由或固定推荐清单掩盖这一问题。

验收输出增加实际操作数、completion_mode、每次工具调用 cost 和各查询命中情况，
便于区分自主回答、预留收尾与候选证据兜底。

运行完整离线测试：python -m unittest discover -s tests -q
运行交互测试：python -X utf8 -m scripts.chat
真实验收入口：python -m scripts.eval_dialogue --live --live-search --question "问题一" --question "追问"
真实验收使用隔离数据库；实时模型和检索需要现有配置及网络。

### 模型控制与分析深度（2026-10-10）

当前 scripts.chat 增加 /settings、/models、/models remote、/model、/profile、/thinking。
配置变更是进程内 dataclass 副本；新客户端初始化成功才替换，保留会话和证据，不改 .env。
档位是预算/思考预设，可通过环境变量绑定模型；未绑定时明确沿用当前模型。
默认输出上限从4000改为8192，深入档位为16384；不强制写长文，也不代表实际消耗。

原开关为true时只是省略disabled，现改为显式请求。固定预算、兼容服务effort、adaptive
分别序列化；不靠模型名自动猜参数，不在错误后静默关思考。DeepSeek官方接口的
budget_tokens会被忽略，故提供独立effort模式，参见
[官方兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/)。自有网关语义不保证与官方一致。
保留工具往返中的思考块，但不展示或存储原始思考；观察元数据记录实际返回模型、
是否返回思考块及usage，区分请求配置与观察。错误回答也记录配置；effort模式不把未发送的
固定预算记成生效值。结构化记忆提取仍独立使用非思考模式。

回答指引强调按问题需要发展少量核心论证、证据与推断、机制与取舍及改变判断的条件。
方法比较可自主选择正文片段，不再暗示重复读摘要就足够；不硬编码最低阅读篇数、
不引入反思Agent、不加固定报告模板。历史由每条截断3000改为最近消息共享24000字符预算，
优先保留最近完整分析，超出时首尾摘录且显式标记省略。

真实验证：当前Flash模型能显式开思考，检索夹具→正文夹具→回答的原生工具链成功；
服务目录查询和进程内交互切换命令成功，deepseek-v4-pro也完成限额真实调用。
effort/high请求在当前网关获得回答和思考块；这些仅证明通路成功，不证明推理强度数值或质量。

分析质量没有宣称全部通过。受控问题中观察到成本边界和机制比较，也观察到把未确证原因
说成根因、无依据的成本倍率/阈值、把工具调用误当重试次数、两句追问中的数字错误。
仅改指引或开思考未稳定消除这些问题；不能把长答案、标题变化、非空或离线通过当成深入分析。
新增 --quality 受控案例及模型配置/调用观察输出，供同模型/同证据的单变量人工验收。
真实论文场景会自主进行2次查询及4次正文读取（两篇各读方法和实验），并输出机制、
实验和边界比较；但仍漏可点击引用、误称读完、存在从片段推断论文整体未做某实验等问题。
来源与实验支持程度尚未逐项核验，不能宣称研究回答质量已经稳定达标。
